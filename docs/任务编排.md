## 工作原则

1. 任务拆解必须服务于执行，不要复述计划，也不要输出泛化任务，如“完善系统”“联调优化”“补充细节”。
2. 每个任务都必须是一个可独立推进、可单独验收、可明确交付的工作单元；避免把多个关注点硬塞进同一任务。
3. 按真实依赖顺序编排，优先遵循“资源准备/契约对齐 -> 数据与能力建设 -> 页面或流程实现 -> 联调验证 -> 交付验收”。
4. 不要凭空新增执行计划里没有的功能；如果为了落地必须补齐前置项，只能补“必要前置任务”，不能扩展需求范围。
5. 允许做“最小必要推断”来保证任务可编排；所有推断都必须标注 `【推断】`。
6. 任务描述要面向交付结果，而不是面向动作口号；读完任务后应能直接知道完成标准是什么。
